# AGENTS.md — unpacker (unified unpacking tool · repo aggregation layer)

> **Reader: an agent who needs to get productive with this tool within a few minutes.**
> Every line comes from reading the source line by line + actually running it on this machine (Windows / Bash, python 3.13).
> Line numbers refer to the current contents of the files; if you change a file, re-check them yourself.
>
> **Repo iron rules**: zero absolute paths; self-built samples must be reproducible; third-party samples are not committed;
> the epistemic boundary **"no known signature seen ≠ not packed"** is passed through verbatim.
>
> **The fundamental difference from the other 5 labs**: `unpacker` **is not a practice lab, it is a tool** — it **read-only** reuses
> the `360jiagu`/`upx_practice`/`ajiami` three labs' detectors/unpackers and aggregates them into one
> **drag-and-drop GUI + CLI + single-file exe**. It produces no samples and reimplements no detection logic.

---

## 0. What this tool is

`unpacker` provides a "drop in a file → decide → route to a solution → verify" pipeline covering the **SO and
DEX two pipelines** of the three self-built labs, and additionally does **cross-project bidirectional regression** (all detectors × all samples confusion matrix).

Design core (`labs.py` docstring):
- **Read-only bridging**: never modifies any lab code; reuses their detectors/unpackers via `sys.path` injection + import by **file path**.
- **Zero absolute paths**: the repo root is derived from `unpacker/`'s own location (rewritable at runtime in the exe scenario).
- **Epistemic boundary pass-through**: each detector's "no known signature seen (≠ not packed)" semantics is preserved verbatim and never rewritten.

## 2. `labs.py` — read-only bridging layer (the source of the interface contract)

### 2.1 Why load by "file path" instead of package import
`_load(module_name, rel_path)` (`:49-66`) uses `importlib.util.spec_from_file_location` to load by **path** — because
**multiple labs have files with the same name** (all three labs have `reset_lab.py`), and package-style import would pollute each other.
Before exec, it injects that lab's `tools/` into `sys.path` (`:61-63`), ensuring its sibling imports (`apkutil` etc.) resolve.
The result is cached with `_SPEC_CACHE` (`:46`).

### 2.2 The three bridged lab modules and reused functions (`LABS` at `labs.py:38-42`)
```
360jiagu     tools/detect_360.py    detect(path, brief, verify, upx) -> dict(verdict,score,b13,is_packed,e_type,e_shnum)
             tools/solve_360.py     solve(src,out,orig,token,upx_path,anchors) -> bool ; load_anchors(...)
upx_practice tools/detect_packer.py same structure as above
             tools/solve_variant.py same structure as above
ajiami       tools/detect.py        apk_features(path) -> f ; verdict(f) -> (结论,规则,朴素,提示,复核)
             tools/unpack_v1.py     main() CLI（一代整体加密脱壳）
             tools/unpack_v2.py     main() CLI（二/三代类抽取脱壳）
             tools/verify.py        sha() / find_anchors()
```
`lab_path(lab, *parts)` (`:104-107`) follows the runtime-rewritable `REPO_ROOT`.
**Each of the three projects also has `reset_lab.py`, which the bridge does not call** (to avoid accidentally changing lab state, `:21`).

### 2.3 Hard constraints on the three labs (must-read before changing a lab)
- The bridge reads the **names and signatures** of `detect(path, brief, verify, upx)->dict` and `solve(...)->bool`;
  for ajiami it reads `apk_features`/`verdict` (a **5-tuple**) and `unpack_v1.main()`/`unpack_v2.main()` (**CLI
  entry points**, invoked with controlled argv).
- Moving `tools/anchors.txt` or changing these names/signatures/prefixes will break the bridge and `regression.py`.

## 3. `analyzer.py` — decision entry point (read-only health check)

### 3.1 File dispatch `sniff_kind(path)` (`:46-62`) — **looks only at magic bytes, not the filename**
`\x7fELF`→`elf`; `dex\n`→`dex`; `zipfile.is_zipfile`→`apk`; otherwise `unknown`.
`unknown` outputs `无法识别的文件类型（非 ELF / 非 ZIP / 非 dex）`.

### 3.2 SO pipeline `analyze_so` (`:66-88`)
**Runs both the 360 and UPX detectors** (`labs.load_360_detect` + `labs.load_upx_detect`), each calling `detect` with
`brief=True, verify=False` (swallowing its prints, `:74-76`), collecting `res + raw_output`.
**Main verdict** (`:126-136`): take the first one with a `verdict` and `is_packed` true; if none, take the first with a verdict;
if still none, pass through `未见已知加固特征（≠未加壳）`.

### 3.3 DEX pipeline `analyze_apk_or_dex` (`:91-112`)
Chooses `apk_features` / `dex_file_features` depending on whether it is a zip, then `verdict(f)`. `is_packed = concl.startswith('已加固')`,
`suspected = concl.startswith('疑似')`.

### 3.4 Honest statement about the relationship between multiple detectors (`:19-23`)
The 360 detector is a **superset** of the UPX detector (it has an extra set of 360 attribution markers); the two agree on
"whether packed" for the same file (verified by cross-running each other's samples), and they diverge only in **packer-type naming**. This tool takes the "first detector to give a known packer-type verdict" as primary.

### 3.5 Actual run (on this machine)
```
$ python unpacker/analyzer.py 360jiagu/samples/so/libtarget_360_variant.so
目标: .../libtarget_360_variant.so   类型: elf
  [360 检测器] 得分=16  b13=False
             结论: ★ 变种 360 加固（UPX! 被 360 改写，结构仍在）
  [UPX 检测器] 得分=16  b13=False
             结论: ★ 变种 UPX 壳（UPX 特征被抹掉，但结构仍在）
  >> 统一结论: ★ 变种 360 加固（UPX! 被 360 改写，结构仍在）
  >> 认知边界：未见已知特征 ≠ 未加固。SO VMP / 非汇聚形态自定义 VMP / 精巧字符串加密 / 完整性校验，均须动态 trace 定性，本工具静态不可确认。
```
**Reading**: the two detectors' **`is_packed` agree (both packed)**, the packer-type naming differs — the 360 version adds a "360" marker. The main verdict takes
the 360 version (the first). **The epistemic boundary is always printed with the verdict** (`:170`).

**DEX pipeline actual run** (`app_packed_v1.apk`):
```

  【判据】B6 所有 dex 的并集中都没有 App 自身包(com.demo.target)的业务类，且存在高熵 asset ...
```

## 4. `unpack.py` — unpacking entry point (decide → route → verify)

### 4.1 CLI
```
python unpacker/unpack.py <input> [-o <outdir>] [--pristine <gold>] [--repo <root>]
```
`input` positional argument; `-o/--outdir` output directory (unspecified = **same directory and prefix as the input**
`<sample name>_unpacked.so/.dex`, see `default_out_path` `:188-196`); `--pristine` golden reference
(if given, do byte-exact; if not, do anchor-only); `--repo` for the exe scenario.

### 4.2 SO solutions (`:80-110`)
- `find_upx_path()` (`:52-62`): **PATH takes priority** (the upx 5.2.1 installed in the user's environment works, verified),
  if not found falls back to `360jiagu/upx.exe` or `upx_practice/upx.exe`.
- `unpack_so_std` (`:80-95`): `upx --force-overwrite -d`.
- `unpack_so_variant` (`:98-110`): reuses the lab's `solve` (candidate token proven restoration → `upx -d`);
  selects `load_360_solve` or `load_upx_solve` by the `lab` parameter; anchors come from `<lab>/tools/anchors.txt`.
  **Key**: explicitly pass `upx_path=upx`, because **setting `UPX` as an environment variable makes upx 5.2.1 parse it as an option string and error out**.
  `_env_no_upxvar()` (`:145-149`) exists precisely to remove `UPX` from the env.

### 4.3 ajiami solutions (`:114-141`) — **controlled argv calling the lab's `main()`**
`unpack_ajiami_v1/v2` temporarily replace `sys.argv` with `['unpack_v1.py', apk, out, '--pristine', ...]`
and then call `mod.main()` (`:120-126`), because the lab script's interface is a CLI `main()` rather than a `solve(...)` function.

### 4.4 Routing `route` (`:212-277`) — **selects the solution by verdict prefix**
```
kind=elf:
  标准 360 / 标准 UPX  → unpack_so_std
  ★ 变种 360           → unpack_so_variant(lab='360jiagu')
  ★ 变种 UPX           → unpack_so_variant(lab='upx_practice')
  其它（B13/疑似/未见）→ 打印"静态不可自动解固"，走内存 dump / 动态 trace
kind=apk/dex:
  已加固：DEX 整体加密 → unpack_ajiami_v1
  已加固：类抽取       → unpack_ajiami_v2
  其它                 → 打印下一步建议（VMP 动态 / SO 侧 dump_fix.py）
```
**Note the prefixes are "contract strings"** — same origin as `regression.py`'s EXPECTED table. Changing a lab's verdict prefix will simultaneously
break the routing here.

### 4.5 Two-level verification `verify_out` (`:153-184`) — **reports the level truthfully**
- **No `--pristine`** → **anchor-only**: prints the first 16 chars of the product's sha256 + `[!] 无字节级对照`.
- **With `--pristine`**:
  - `elf` → `byte_diff_excl_etype` (`:69-76`, **ignores the e_type offset 16..17**), 0 differences means byte-exact;
  - `dex/apk` → matching sha256 means byte-exact; if they differ, calls `verify.find_anchors` to give anchor-missing details.

### 4.6 Overwrite protection (`:199-208`)
`unique_out_path`: if the product already exists, appends `_1/_2/…` (up to 999), **never silently overwrites**.

### 4.7 Actual run (on this machine, three levels)
**Variant SO (byte-exact)**:
```
[*] ① 判定（只读体检）...
    判定结论: ★ 变种 360 加固（UPX! 被 360 改写，结构仍在）
[*] ② 按壳种路由解法。产物目录: C:\...\tmp
    候选 token b'JG!!' x4 -> upx -t OK
[+] 确定被篡改的 token: b'JG!!' -> 还原为 'UPX!'（共 4 处）
[+] 解包成功: .../unpacked.so (43888 bytes)
[*] 与黄金 libtarget_orig.so 对照: 大小 43888 vs 43888
[+] 除 e_type 外 0 字节差异 => 内容一致，解固成功（byte-exact）
[+] 解固成功（验证等级: byte-exact）
```
**First-gen APK (byte-exact)**: `sha256 = e330d299...` → `[+] sha256 与黄金一致 => 解固成功（byte-exact）`.
**Standard SO without `--pristine` (anchor-only)**: `[!] 无字节级对照...` → `[+] 解固成功（验证等级: anchor-only）`.
(The last one's product lands in `unpacked_1.so` — because `unpacked.so` already exists, `unique_out_path` auto-numbers it.)

## 5. `regression.py` — cross-project bidirectional regression (repo-wide confusion matrix)

### 5.1 Why it is needed (`:5-12`)
Each of the three labs' own `check_*.py` only validates its own detector within its own sample domain. `unpacker` aggregates all detectors,
so it must validate **"all detectors × all samples"**: positive (known packers must be classified correctly, guarding against "over-tuning that misses real packers"),
negative (clean samples must land on "no known signature seen", guarding against false positives), and **cross** (feed project A's samples to project B's detector; the verdict direction
must agree).

### 5.2 Expectation table `EXPECTED` (`:43-68`) — 19 samples
360jiagu 4 + upx_practice 4 + ajiami 11 (including the epistemic-boundary samples `app_vmp`/`app_so_packed` expecting `suspect`,
and the negative samples `app_orig`/`neg_*` expecting `clean`). **The expected prefixes are taken directly from each lab's assertions** — if a lab's expectation changes
and this table is not synchronized, the failure output will explicitly note "the expectation table may be out of sync with the lab assertions".

### 5.3 Cross-validation `CROSS_CHECKS` (`:72-77`)
360 samples fed to the UPX detector, UPX samples fed to the 360 detector, **the `is_packed` direction must agree** (packer-type naming may differ).
`classify` (`:80-99`) folds the result into `packed/suspect/clean/unknown-kind`.

### 5.4 Actual run (on this machine)
```
$ python unpacker/regression.py
  [PASS ] 360jiagu/samples/so/libtarget_orig.so                期望=clean 实得=clean
  [PASS ] 360jiagu/samples/so/libtarget_360.so                 期望=packed 实得=packed
  [PASS ] 360jiagu/samples/so/libtarget_360_variant.so         期望=packed 实得=packed
  [PASS ] 360jiagu/samples/so/libtarget_stripped.so            期望=suspect 实得=suspect
  ... (upx_practice 4 + ajiami 11)
SO 检测器交叉验证（360 ↔ UPX，is_packed 方向必须一致，壳种命名可不同）:
  [PASS ] 360jiagu/samples/so/libtarget_360.so  360=加壳(标准 360 加固（改版 U) | UPX=加壳(标准 UPX 壳（特征完整）)
  ...
结果: 19/19 通过, 交叉 4/4 通过
[+] 全部通过。
```
`--json` outputs a structured `{matrix, cross, pass, fail}` (checked on this machine; `--json` uses `ensure_ascii=False`,
so on a Windows console without `PYTHONIOENCODING=utf-8` the Chinese will be mojibake — **to read the JSON, set that env var or redirect to a file**).

## 6. `main.py` — exe entry point and repo location

### 6.1 Subcommands (`:111-177`)
```
unpacker.exe                    # no args → GUI (double-click main entry point)
unpacker.exe gui                # GUI
unpacker.exe analyze  <文件>...  # → analyzer.main_with_repo
unpacker.exe unpack   <文件>     # → unpack.main_with_repo
unpacker.exe regression         # → regression.main_with_repo
unpacker.exe <某文件路径>        # drop onto the icon → handled as analyze
```
`--repo <path>` is a **global argument**, stripped before dispatch (`:100-109`).

### 6.2 Repo location `_resolve_repo` (`:36-62`) — **five tiers**
`--repo` (CLI) > `ANDROID_REVERSE_LABS` (env) > exe's directory > **search up to 4 levels from the exe's directory** for a directory containing
`360jiagu/upx_practice/ajiami` > the exe's built-in fallback copy (`sys._MEIPASS/labs_bundle`).
Not found → `_popup_error` (tk message box, `:77-86`) + a hint with three remediation paths.

### 6.3 No-console fallback (`:92-98`)
The GUI exe is packaged with `--noconsole`, so `sys.stdout/stderr` are `None` — detectors printing to stdout would blow up.
main.py replaces them with an `os.devnull` safe stream; the GUI's real output is taken over by `gui.py` in a thread using a **queue**
(`:92-98` comment).

## 7. `gui.py` — graphical interface (tkinter + tkinterdnd2)

- Three layout groups (docstring): ① select target (**whole-window drag-and-drop** + browse button) ② execute (decide / unpack / regression matrix +
  optional golden sample + optional product location) ③ output (`[!]/[*]/[+]` verbatim, can be cleared/copied).
- Behavior is **exactly the same as the CLI**, it just pipes stdout into the text area (`_QueueWriter` `:61-71`).
- **Long tasks run in a background thread**, the UI does not freeze; buttons are disabled while running (`:104-132`).
- **`_install_no_window_subprocess()`** (`:73-92`): adds a default `CREATE_NO_WINDOW` to all labs' `subprocess` calls — solving "every step flashing a black box in the GUI" **without changing lab code**
  (monkey-patching `subprocess.Popen.__init__`).
- Without `tkinterdnd2` it degrades to pure click-selection (`:44-47`; the exe has it built in, so this path is generally not reached).

## 8. `build_exe.py` — PyInstaller packaging

- `prepare_bundle()` (`:41-61`): copies the three labs' `tools/*.py` + `anchors.txt` into
  `build/labs_bundle/<lab>/tools/`.
- `build_one('unpacker', console=False)` (`:64-98`): `--onefile`, `--add-data build/labs_bundle;labs_bundle`,
  `--add-data app_icon.ico;.`, `--collect-all tkinterdnd2`, `--icon app_icon.ico`, entry point `main.py`.
- **Single product**: `dist/unpacker.exe` (GUI, `--noconsole`) — **the same exe also works as a CLI in a terminal**
  (with a real console, print behaves normally; double-click = open GUI). The old `unpacker-cli.exe` has been removed (`:112-114`).
- **No third-party binary is packaged in** (upx.exe goes through PATH/repo location; neither keystore nor exe is involved, `:21`).
- **Consistency between the exe and the source**: the lab copy built into the exe is a snapshot **at packaging time**; **when a repo is found, the repo's is preferred**
  (in sync with the lab), and the built-in copy is used only when no repo is found (`main.py` docstring + `_resolve_repo`). **So after changing lab
  logic, the exe uses the old copy only when there is "no repo"** — the source scenario is unaffected.

## 10. Pitfalls (root causes)

1. **The `UPX` environment variable makes upx 5.2.1 error out**. upx parses `UPX` as an option string, and a path value errors directly. Solution:
   `unpack.py:104` explicitly passes `upx_path` + `_env_no_upxvar()` removes `UPX` from the env (`:145-149`).
2. **`unpacker` does not "understand" new packer types**. Routing relies on **literal prefix** matching (`route` `:231-274`); if a lab changes a
   verdict prefix, the routing silently falls into the "statically cannot auto-unpack" branch. Changing a prefix requires synchronizing both `route` and `regression.EXPECTED`.
3. **`labs_bundle/` is a snapshot, not the source of truth**. It is a product of `prepare_bundle()`; changing lab logic does not refresh it automatically,
   you must re-run `build_exe.py`. In the **source scenario**, `_resolve_repo` prefers the real repo, so it is unaffected.
4. **The exe's repo location is five tiers**. When there is no repo, only the built-in copy is available (**not guaranteed to be in sync with the lab's latest code**);
   if no repo is found → `analyzer`/`unpack`/`regression` are all unavailable (it will hint at three remediation paths).
5. **Under `--noconsole`, `sys.stdout` is None**. Lab detectors printing to stdout would blow up — main.py falls back to
   `os.devnull` (`:92-98`), and the GUI takes over output with a queue. Do not assume stdout is valid in a console-less exe.
6. **Verification is two-level and reported truthfully**. Without `--pristine` there is only **anchor-only** (not byte-exact);
   do not treat anchor-only as "fully identical". `verify_out` (`:153-184`) explicitly says `[!] 无字节级对照`.
7. **SO byte comparison ignores e_type** (offset 16..17). `byte_diff_excl_etype` (`:69-76`) — because
   UPX packing changes `e_type` (DYN↔EXEC), a known fact in 360jiagu/upx_practice.
8. **Products land in the input file's directory by default** (not collected into any directory), and if they already exist they are numbered `_1/_2`. Only `-o` collects them into a specified directory.
9. **`regression.py --json` is mojibake on a Windows console without UTF-8 set** (`ensure_ascii=False`).
   Set `PYTHONIOENCODING=utf-8` or redirect to a file.
10. **`sniff_kind` looks only at magic bytes, not the extension**. Changing the suffix will not fool the dispatch — this matches the repo discipline of "never judge by filename alone".

## 11. Quick reference (all verified on this machine)

```bash
# --- decide (read-only health check) ---
```

## 12. Reading order for a new agent

1. Read `labs.py` — it is **the source of the interface contract**; first figure out "which function of each lab the bridge reads, with what signature".
2. Read `analyzer.py`'s `sniff_kind`/`analyze` — how decisions are dispatched and how the main verdict is chosen.
3. Read `unpack.py`'s `route`/`verify_out` — solution routing (prefix matching) and two-level verification.
4. Run §11's analyze/unpack (all three verification levels) and regression, and compare against the output on this machine.
5. Read `regression.py`'s `EXPECTED`/`CROSS_CHECKS` — it is the map of "what changing a lab will break".
6. Finally read `main.py`/`gui.py`/`build_exe.py` — exe packaging, GUI repo location, and the no-console fallback.
